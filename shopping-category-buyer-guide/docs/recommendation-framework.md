# Recommendation Framework

## Goal

把“最近看到哪些价格”转成“现在应该怎么买”。

## Recommendation Dimensions

每次建议至少从这些维度看：
- 当前价格是否接近好价
- 当前价格相对历史低价处在什么位置
- 关键参数是否真的强
- 同价位性价比是否成立
- 口碑是否稳定
- 是否适合用户的使用场景
- 信息是否足够完整
- 是否存在更好的替代项

## Required Recommendation Answers

最终建议至少要明确回答：
- `最推荐买哪个型号`
- `它的合适价格是什么`
- `当前推荐清单里还有哪些型号性价比也不错`
- `是否建议现在下单`

## Price Band Rule

尽量给出价格带，而不是只有一个点价。

例如：
- `闭眼买价`
- `可以入手价`
- `不着急可以等等的价`

如果历史价格不足：
- 结合当前主流成交价、活动复杂度、竞品对比给出相对价格判断
- 同时明确标注 `历史样本不足`

## Historical Price Rule

推荐前必须先判断价格位置，而不是只看当前页面价格。

但历史低价只是一种参考，不是唯一标准，原因包括：
- 本地抓价往往不是从产品上市第一天就连续覆盖
- 不同平台、券后口径、套装口径可能不完全一致
- 有些型号即使价格接近历史低位，也可能因为参数落后或不适配需求而不划算

至少要区分三层：
- `exact 型号近期最低价`
- `exact 型号近期常见价`
- `当前价离近期最低价差多少`

输出时要尽量明确写成：
- `今天是新低`
- `今天接近近期低位`
- `今天能买，但不是新低`
- `今天明显高于前几天`

如果 only 能拿到系列组历史价：
- 不能直接把系列最低价当成 exact 型号历史低价
- 必须写明这是 `系列口径`
- 推荐确定性要下降一档

如果 exact 型号和系列口径同时存在：
- exact 型号优先
- 系列口径仅作为补充背景

## Four-Tier Output

最终输出必须固定按以下四档组织：
- `特别值得买`
- `适合买`
- `着急才买`
- `不建议买`

不再把“历史状态等级”单独作为最终主输出。  
历史价格位置属于证据之一，最终分档必须由综合判断得出。

## Decision Factors

每个型号的最终分档，至少综合以下因素：
- `价格位置`
  当前价相对本地已抓历史、新近低位、常见成交区间的位置
- `参数竞争力`
  在同价位里是否明显偏强、均衡，还是有硬伤
- `性价比`
  当前价格对应的参数、体验、品牌和口碑是否划算
- `需求适配`
  是否符合用户预算、场景、偏好、人群约束
- `口碑稳定度`
  是否存在高频槽点、明显质量争议或售后风险
- `信息完整度`
  关键参数或价格证据是否足够完整，能否支持高置信结论

## Tier Rules

### 1. 特别值得买

通常同时满足：
- 当前价格处在明显低位，或即使不是最低也仍然非常有竞争力
- 同价位参数、体验或综合能力明显占优
- 适配用户需求，没有被更优替代项压住
- 关键信息完整，结论置信度高

注意：
- 不能只因为“接近历史低价”就放进这一档
- 只要参数档位、适配度或信息完整度不过关，就不应给到这一档

### 2. 适合买

常见情形：
- 当前价已经进入合理入手区间
- 参数和体验整体过关，性价比成立
- 适合目标需求，但未必达到“错过可惜”的强确定性

### 3. 着急才买

常见情形：
- 产品本身不差，但当前价不算特别漂亮
- 或价格还行，但存在更优替代项
- 或适配度一般，仅在用户有明确时间压力时可接受

### 4. 不建议买

常见情形：
- 当前价明显不划算
- 参数、口碑或需求适配明显不占优
- 关键证据不足，暂时不能支撑积极推荐
- 已有更强、更稳或更适配的替代项

如果历史样本不足：
- 输出 `历史样本不足`
- 继续分档，但要主动降低历史价格因素权重
- 如信息缺口太大，优先放入 `不建议买` 或最多 `着急才买`

## Recommendation Tiers

推荐可分为：
- `首推`
- `次选`
- `预算友好`
- `观望`

## Decision Rule

### 1. 首推

满足大部分条件：
- 参数在当前价格带明显占优
- 口碑问题不明显
- 当前价格已经接近 exact 型号的近期低位，或本身就是新低
- 对目标用户场景适配度高

### 2. 次选

常见原因：
- 价格略高但参数更强
- 或参数略弱但价格特别合适
- 或适合不同偏好人群
- 或当前价能买，但离近期最低价还有一点距离

### 3. 预算友好

常见原因：
- 核心需求能满足
- 价格显著更低
- 但会在参数、体验或长期耐用性上让步

### 4. 观望

常见原因：
- 当前价格不够好
- 当前价明显高于最近几天/几轮的低位
- 口碑明显有坑
- 参数公开不透明
- 存在更优替代

## Output Structure

建议输出包含：
- 四档结论摘要
- 主力型号横向比较
- 当前价 vs 近期低价
- 分预算建议
- 分人群建议
- 当前是否值得下单
- 等待什么条件再买

其中“主力型号横向比较”必须表格化输出，而不是只用段落描述。
而且更推荐按四档分组展示表格，先把最值得用户看的放前面。

推荐的最小列集：
- 型号
- 型号链接
- 当前价
- 全历史最低价
- 近期最低价
- 价格位置判断
- 四档判断
- 关键参数
- 配置细节
- 口碑摘要
- 性价比判断
- 需求适配
- 信息完整度
- 现在买/等等

如果当前轮次已经存在明确标杆，也建议补一列：
- `相对标杆`
- `性能差距是否值价差`

## Writing Rule

- 尽量说人话，但结论要具体
- 避免只说“不错”“一般”“中等”
- 能给硬参数就给硬参数
- 能给价格带就给价格带
- 能给历史低价和当前差额就给出来
- 但不要把历史低价当成唯一依据
- 能给对应 deal 链接就直接放进表格
- 如果用了标杆法，必须把“性能差距值不值这个价差”写明白
- 能说清楚适合谁/不适合谁就直接写出来
