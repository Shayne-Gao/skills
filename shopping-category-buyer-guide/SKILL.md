# Shopping Category Buyer Guide

This skill turns a shopping category request into a reusable buying workflow:
- search recent SMZDM deals for the category
- normalize and group models
- research key specs from external sources
- summarize public praise and complaints
- recommend what to buy, fair prices, and whether to order now
- persist model specs and current-round price records for future refreshes

Use this skill when the user wants to:
- 研究一个品类最近有哪些好价
- 输入一个品类后做选购建议，例如“除螨仪”“电视”“电饭煲”
- 比较多个型号的关键参数、口碑和性价比
- 判断什么价位算好价、现在值不值得买
- 沉淀某个品类的本地价格库、型号参数库、推荐结论

## Scope

本 skill 负责以下闭环：
- 从什么值得买搜索页抓取该品类近期好价
- 去重、过滤噪音、按型号归一化
- 补充每个主力型号的关键参数与来源
- 汇总“大家常夸什么、常吐槽什么”
- 按多个维度给选购建议
- 将价格记录、型号参数、结论文件落盘到本地目录

## Non-Goals

本 skill 不负责：
- 代替真实下单决策中的最终付款链路
- 伪造未核实的参数、口碑或历史低价
- 只看当前页面价格就直接给“闭眼买”结论

如果用户只是要抓全站最新什么值得买内容，不带特定品类分析，优先使用 `fetch_smzdm_latest_items`。

## Input Contract

最低输入：
- 一个品类关键词，例如 `除螨仪`

推荐补充输入：
- 预算区间
- 使用场景
- 核心诉求，例如“清洁能力”“噪音”“是否适合长辈”“是否要低维护”
- 是否需要 HTML 宽表 / 在线页

如果用户没补充，先按通用家庭场景做第一轮研究，再明确说明默认假设。

## Required Outputs

每次执行至少应交付：
- 本轮看了哪些什么值得买结果页
- 抓到多少条候选
- 归一后有哪些主力型号
- 每个主力型号的关键参数和口碑摘要
- 一张本轮主力型号参数对比表
- 不同预算/场景下的推荐结论
- 一段按固定四档组织的结论：
  - `特别值得买`
  - `适合买`
  - `着急才买`
  - `不建议买`
- 明确回答：
  - `最推荐买哪个型号`
  - `什么价格算合适`
  - `当前有哪些型号性价比不错`
  - `现在是否建议下单，还是继续等`

参数对比表不是可选项。  
只要本轮抓了新数据，就必须输出对比表；不能只给纯文字结论。

表格也不是随便拼几列就算完成。  
默认至少要包含：
- `型号`
- `型号链接`
- `今天价格`
- `当前判断`
- `与标杆/参考线的关系`
- `关键配置细节`
- `现在是否建议下单`

默认展示顺序也必须服务于选购决策，而不是只做一个大杂烩宽表。  
优先按四档分组展示：
- 先 `特别值得买`
- 再 `适合买`
- 再 `着急才买`
- 最后 `不建议买`

注意：`标杆` 只能作为价格锚点，不能替代性能判断。  
如果引入标杆，必须继续明确回答：
- 它和标杆相比到底强在哪里、弱在哪里
- 这些性能差距是否值当前价差
- 不能只写“比标杆贵/便宜”就直接下结论

## Persistence Rule

每个品类都应在 `shopping-research/<category_slug>/` 下持续沉淀，至少保留：
- `*_latest_capture.json`
- `*_model_specs_registry.json`
- `*_price_history_cache.json`
- `*_compare_table.md` 或 `*_compare_table.html`
- `*_buying_advice.md` 或 `*.html`

如已存在历史文件：
- 优先增量更新，不要无理由覆盖整库
- 型号参数优先 patch 更新
- 新一轮价格记录单独更新 capture 文件
- 历史价格缓存应持续并入，不要只看最近一轮

具体目录与字段见：
- `docs/data-layout.md`
- `docs/workflow.md`
- `docs/spec-research-playbook.md`
- `docs/recommendation-framework.md`

## Core Operating Rules

1. 先抓近期好价，再做参数和推荐，不要脱离实际在售价格空谈。
2. 先按型号归一再研究参数，避免同款不同标题重复分析。
3. 参数只写可验证硬参数；不能稳定核实就写 `null` 或在 warning 说明。
4. 必须区分：
   - 原生参数
   - 营销口径
5. 评价部分优先提炼稳定共识，而不是只摘一条极端评论。
6. 推荐结论必须综合判断，至少同时看：
   - 当前价格
   - 历史价格位置（仅作参考，不是唯一标准）
   - 型号能力 / 关键参数
   - 同价位性价比
   - 常见口碑
   - 适用人群与用户需求匹配度
   - 信息完整度与结论置信度
7. 判断“现在能买吗”时，必须先回答价格上下文，但不能只按历史低价拍板：
   - 这个 exact 型号前几天是不是更便宜
   - 当前价离近期低价差多少
   - 当前价是新低、接近低位，还是明显涨回去
   - 即使价格位置不错，它的参数、性价比和适配度是否仍然成立
8. 如果只能拿到系列混合价，不能直接把系列最低价当成 exact 型号最低价；要明确写这是“系列口径”还是“exact 型号口径”。
9. 每次推荐前，都应优先查询本地 `price_history_cache`，把当前价格放到“全部已抓历史”里判断，而不是只看最近两三天。
10. 最终输出必须优先按以下四档结构组织，不要临时换口径：
   - `特别值得买`
   - `适合买`
   - `着急才买`
   - `不建议买`
11. `特别值得买` 不能只因为接近历史低价；还应同时满足：
   - 同价位里参数或体验明显占优，或至少没有明显短板
   - 适配当前用户需求
   - 没有被更好的同价位替代项压住
   - 关键信息足够完整，结论置信度较高
12. 如果历史价格样本不足，要明确写 `历史样本不足`，并把历史结论权重下降。
13. 如果关键参数不完整、口碑分歧大或适配度不明确，要降低推荐确定性；此类型号原则上不要轻易放进 `特别值得买`。

## Standard Flow

### 1. Clarify category and scenario

确认：
- 品类关键词
- 是否有预算/用途/特殊人群

### 2. Capture recent SMZDM deals

围绕品类关键词抓最近什么值得买搜索结果，记录：
- 标题
- 价格
- 平台
- 链接
- 标签
- 时间
- 值率/评论等热度信息

### 3. Normalize models

对候选条目做：
- 去重
- 噪音过滤
- 型号抽取
- 系列归组

### 4. Research model specs

对核心型号从品牌官网、官方电商参数页、主流参数站、评测等交叉核实：
- 关键硬参数
- 参数冲突
- 明确来源

### 5. Summarize public feedback

提炼每个型号的：
- 常见优点
- 常见问题
- 适合谁
- 不适合谁

### 6. Produce buying advice

至少给出：
- 最推荐型号
- 好价带
- 当前最值得关注的替代项
- 是否建议现在下单
- 观望条件是什么
- 按四档排列的结果：
  - `特别值得买`
  - `适合买`
  - `着急才买`
  - `不建议买`

在输出上述结论前，必须先完成价格位置判断：
- exact 型号近期最低价
- exact 型号近期常见成交区间
- 当前价相对近期最低价的差额
- 如果 exact 数据不足，再退化为系列组口径，并明确标注置信度下降

但最终分档不能只看价格位置，还要补齐：
- 当前价位下的参数竞争力
- 是否存在更强或更均衡的替代项
- 是否适配用户预算、场景和偏好
- 当前信息是否足够完整到支持明确推荐

同时必须产出一张可读的型号对比表，至少包含：
- 型号
- 型号链接
- 当前价
- 全历史最低价
- 近期最低价
- 价格位置判断
- 四档判断
- 关键参数
- 配置细节
- 口碑摘要
- 性价比判断
- 需求适配
- 信息完整度
- 现在是否建议下单

如果本轮已经存在明确标杆或参考锚点，例如 `75R69A @ 3000 左右`，表格里还应额外给出：
- 与标杆相比是 `更贵但更强`
- 还是 `更便宜但更弱`
- 或 `既没更强，也没便宜到位`
- 最好再补一列 `性能差距是否值这个价差`

如果用户明显更关心“怎么买”，分组表应优先于单张总表；必要时可以同时给：
- 一组按四档分开的决策表
- 一张总览汇总表

### 7. Persist artifacts

把本轮结果落盘，方便后续只刷新价格或补充新型号。
其中对比表也必须落盘，不能只在对话里临时展示。

## Example Triggers

- “帮我做个除螨仪选购建议”
- “从什么值得买看看最近电饭煲好价”
- “这个品类有哪些型号最值得买”
- “什么价格算好价，现在能买吗”
- “把这个品类做成长期跟踪的选购库”
