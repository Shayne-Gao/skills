# Lesson 1 · 让 Agent 第一次"动手"：操作本地文件

> 一句话定位：把 L0 那次"随手存"升级成**结构化、可复用**的本地数据，为 L2 做可视化打地基。

---

## 1. 你将学会

- [ ] 我能让 Agent **按我指定的目录、文件名、字段结构**写入数据
- [ ] 我能区分"自由文本"和"结构化数据"，并知道为什么 PM 应该优先要后者
- [ ] 我能让 Agent 在写入前先**预览方案**，避免一上来就写错

---

## 2. 背景小知识

L0 你看到 Agent 能动手，但写出来的 `news.md` 是 markdown 表格——好看，但**不好被下游消费**。

PM 工作里有两种数据形态：

| 形态 | 长什么样 | 适合 |
|------|----------|------|
| 自由文本 | 一段话 / 一篇文档 | 给人读 |
| 结构化数据 | JSON / CSV / 表格 | 给程序读、给下一个 Agent 步骤读 |

> 一旦你想"做可视化、做筛选、做月度对比、做自动化"，**结构化数据就是必选项**。
> L2 我们要让 Agent 把这堆数据渲染成 HTML dashboard，所以本讲就要先把数据存对。

直觉口诀：**先想清楚下游谁来用，再决定存什么格式。**

### Step 1 · 先和 Agent 一起定 schema（字段定义）

> 这一步比直接喊"开始抓"重要 10 倍。**没 schema 的 Agent，下游永远在返工。**

**🎯 你要做什么**
让 Agent 先给你一个字段定义草案，你来 review 和确认。

**⌨️ 你输入什么**

```
我要做一个"行业新闻周报"主线任务，每周抓一次新闻，存到本地，下游会用这些数据做 HTML 可视化。

帮我设计 news.json 的 schema（字段定义），要求：
1) 字段尽量原子化（一个字段只装一种信息）
2) 必含：标题、来源媒体、原文链接、发布时间、行业标签、一句话摘要、重要性分（1-5）
3) 给我两份产物：
   - schema/news.schema.md：字段名、类型、是否必填、示例值
   - 一条 mock 数据 sample.json，按 schema 长什么样

先不要去抓真实新闻，先把这两份产物给我看。
```

**👀 预期看到什么**
- Agent 在 `pm-agent-lab/news-lab/schema/news.schema.md` 写一份字段表
- 在同目录或临时位置生成一条 `sample.json` 示例
- 自然地停在这里**等你确认**

**📝 你要在这里做的事**
认真 review schema：
- 有没有字段是"两件事塞一起"的？比如"来源(标题)" → 拆成 `source_name` 和 `source_title`
- 行业标签是单选还是多选？（PM 视角：多选，所以用数组）
- 重要性分由谁打？是 Agent 自己评估的，还是你后续手工调整的？要不要再加一个 `editor_note` 字段？

把你想到的修改用一句话告诉 Agent，让它更新。**这个对话本身就是 PM 工作的高频姿势：用自然语言定义数据契约。**

**⚠️ 如果出错怎么办**
- 偏差 A：Agent 直接开始抓新闻了 → 纠偏：

  ```
  停一下。我现在不需要新闻，只需要 schema 设计。请只产出 schema/news.schema.md 和一条 mock sample.json，等我确认后再开始抓。
  ```

- 偏差 B：schema 字段堆了 20 多个 → 纠偏：

  ```
  字段太多了。请按"一周后我用这些数据做 HTML dashboard"的最小必要集合精简到 8 个字段以内，其它放进 optional。
  ```

### Step 3 · 给数据加一层"质量自检"

> PM 不能等下游用数据时才发现质量问题。让 Agent 写完后**自己 QA 一遍**。

**🎯 你要做什么**
让 Agent 立刻对刚写入的数据做一遍体检。

**⌨️ 你输入什么**

```
对刚写入的 news.json 做一次自检，按下面清单逐项给我答案：
1) 总条数 / 必填字段缺失的条数 / 重要性分布
2) 有没有重复新闻（标题或链接重复）
3) 时间字段是否都在过去 7 天范围内
4) 行业标签里有没有明显错的、或者粒度不一致的（比如有的写"AI"有的写"AI Agent"）
5) 给出 3 条改进建议，但不要直接动数据，先告诉我。
```
