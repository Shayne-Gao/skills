## 2. 背景小知识

**Vibe Coding** 不是一种编程语言，而是一种**工作方式**：

> 你描述意图（vibe），Agent 负责实现（coding）；你不审代码，只审**结果**。

它对 PM 的意义是巨大的：

- 过去：你想验证一个交互想法，要排期、找研发、几天后才看到 demo
- 现在：你 30 分钟内就能拿到一个**可点击、能筛选、能排序**的 demo 挂给老板

不是要 PM 替代研发，而是让你把"想法 → 可被讨论的产物"的距离压到最短。

> 红线：Vibe Coding 出来的产物**默认是一次性的**——能跑、能演示、能验证想法，但不要直接拿去当生产代码。该交研发还是交研发，但交的不再是 PRD，而是已经验证过的 demo。

## 9. 给 PM 的小结：vibe coding 的"三档止步线"

| 档位 | 长什么样 | 止步条件 |
|------|----------|----------|
| 一次性 demo | 双击能打开、能演示一个想法 | **本讲 = 一档**。验证完想法就停 |
| 个人小工具 | 可以反复打开使用、有数据更新流程 | L5 把它封装成 Skill 后再升档 |
| 团队产品 | 多人用、有权限、要维护 | **永远交给研发**，不要自己接 |

**90% 的 PM 场景一档就够。** 不要把自己拖进维护泥潭。
