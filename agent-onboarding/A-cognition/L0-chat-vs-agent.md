# Lesson 0 · Chat vs Agent：差别到底在哪

> 一句话定位：用同一个问题做两遍，**亲手感受**普通 LLM 与 Agent 的本质差别。

---

## 1. 你将学会

- [ ] 我能用一个具体例子说清"Chat 和 Agent 差在哪"，不用任何术语

---

## 2. 背景小知识

把 LLM 想象成一个**只会动嘴、不会动手的超级实习生**。

- 普通 Chat：你问一句，它答一句。它聪明但被关在屋子里——不能上网、不能写文件、不能点按钮。
- Agent：同一个实习生，但**给了它键盘、浏览器、文件柜的钥匙**。你给它一个目标，它会**自己决定先做什么、再看结果、再决定下一步**，直到完成或卡住。

差别不在模型大小，而在**"它能不能动手 + 能不能多步连贯地动"**。

> 后面所有讲义都建立在这一个直觉上：Agent = LLM × 工具 × 自主循环。

## 4. 实战任务

我们让两个窗口完成**同一件事**："帮我整理过去一周 AI Agent 行业的重要新闻"。

注意观察的不是答案本身，而是**它们处理问题的方式**。

---

### Step 1 · 在 Chat 窗口（窗口 A）问一遍

**🎯 你要做什么**
让普通 Chat 给你"过去一周 AI Agent 行业新闻"。

**⌨️ 你输入什么**

```
帮我整理过去一周 AI Agent 行业的 5–10 条重要新闻，每条带：标题、来源、一句话摘要。
按重要性排序。
```

<details><summary>📋 切换到「需求池整理」场景的 prompt</summary>

```
帮我把下面这一周散落在各处的需求线索（飞书 IM 提到的、邮件里收到的、用户访谈摘录），
整理成 5–10 条候选需求，每条带：需求一句话描述、来源、初步价值判断。
按重要性排序。

[这里你想象贴入：3-5 段杂乱的来源原文]
```
</details>

<details><summary>📝 切换到「会议纪要跟进」场景的 prompt</summary>

```
帮我从下面这一周的 3 段会议纪要里，提取出 5–10 个待办与决策事项，
每条带：事项一句话描述、归属人（如纪要里有提到）、紧急度。
按紧急度排序。

[这里你想象贴入：3 段会议纪要全文]
```
</details>

**👀 预期看到什么**
- 它会**直接给一段 markdown 列表**，看起来很整齐。
- 仔细看会发现一个或多个问题：
  - 时间不准：很可能是几个月前甚至去年的新闻
  - 来源含糊："据某媒体报道"
  - 链接是编的，点开 404
  - 你问"刚才那些来源能确认吗"，它会道歉但还是给不出真链接

**📝 把这些观察记下来**（开个空文档随手记，3–5 条即可），后面 Step 3 会用。

**⚠️ 如果出错怎么办**
- 它说"我无法访问实时信息"——**这就是答案，恰恰证明它是普通 Chat**。继续下一步。
- 它居然给了带链接的真实新闻——多半是它接了搜索插件，已经偏 Agent 了。换一个不带搜索的更纯粹的 Chat 再试一次。

---

### Step 2 · 在 Agent 窗口（窗口 B）问一遍

**🎯 你要做什么**
同样的问题给 Agent，但**先什么都不要补充**，看它自己怎么动。

**⌨️ 你输入什么**

```
帮我调研过去 7 天 AI Agent 行业的 5–10 条重要新闻，每条带：标题、来源链接、发布日期、一句话摘要。
按重要性排序。
```

<details><summary>📋 切换到「需求池整理」场景的 prompt</summary>

```
请你扮演 PM 助理。读取我桌面上的这一周需求来源原文（我把它们汇总在
pm-agent-lab/backlog-lab/L0-demo/sources.md 里，你可以直接打开读），
帮我整理成 5–10 条候选需求，每条字段：
- 需求一句话描述（动词+宾语+受益对象）
- 来源（具体到哪条飞书消息 / 哪段访谈）
- 初步价值判断（1-2 句话）
- 我建议的下一步动作
按"价值大、待办近"两条线综合排序。
```
</details>

<details><summary>📝 切换到「会议纪要跟进」场景的 prompt</summary>

```
请你扮演 PM 助理。读取我桌面上 pm-agent-lab/meeting-lab/L0-demo/notes/
目录下这一周所有 .md 会议纪要，提取出 5–10 个待办与决策事项，每条字段：
- 事项一句话描述
- 归属人（纪要里若没有，就标"待指派"）
- 紧急度（高/中/低）+ 截止建议日期
- 该事项关联的会议名/日期
按紧急度排序，并在末尾告诉我"哪几条没有归属人需要我决定"。
```
</details>

**👀 预期看到什么**
- 它**不会立刻给答案**，而是会先做一连串动作：
  - 调用 `web search` / `web fetch` 搜索新闻
  - 打开几个网页读内容
  - 可能告诉你"我搜到 X 条，正在整理"
- 最终给你的列表里，链接可点、日期真实、来源具体。

**📝 重点观察**：Agent 在动手之前你能看到它的"思考-动作-观察"循环。这就是它和 Chat 的根本差别。

**⚠️ 如果出错怎么办**
- 偏差 A：Agent 直接给了一段没有链接的总结 → 纠偏 prompt：

  ```
  你刚才有真实联网吗？请重新做：每一条必须给真实可点击的来源链接和发布日期，找不到就老实说找不到。
  ```

- 偏差 B：Agent 一直转圈不出结果 → 纠偏 prompt：

  ```
  把你的搜索过程拆成 3 步：1) 搜索关键词清单；2) 你打算访问的前 5 个网站；3) 摘录的字段。先把这 3 步告诉我，再开始执行。
  ```

### Step 3 · 让 Agent 把结果"存到本地"——这是 Chat 完全做不到的

**🎯 你要做什么**
让 Agent 把刚才的新闻清单**写到你电脑的指定目录**。这是本讲最关键的一步——**让你亲眼看到 Agent 在动手**。

**⌨️ 你输入什么**

```
把刚才整理的新闻清单写到我本地：
- 路径：pm-agent-lab/news-lab/L0-demo/news.md
- 格式：markdown 表格，列分别是 标题 / 来源 / 日期 / 摘要 / 链接
- 如果目录不存在，请先创建
完成后告诉我你创建/修改了哪些文件。
```

<details><summary>📋 切换到「需求池整理」场景的 prompt</summary>

```
把刚才整理的需求候选清单写到我本地：
- 路径：pm-agent-lab/backlog-lab/L0-demo/backlog.md
- 格式：markdown 表格，列分别是 需求描述 / 来源 / 价值判断 / 下一步 / 提出日期
- 如果目录不存在，请先创建
完成后告诉我你创建/修改了哪些文件。
```
</details>

<details><summary>📝 切换到「会议纪要跟进」场景的 prompt</summary>

```
把刚才整理的待办与决策清单写到我本地：
- 路径：pm-agent-lab/meeting-lab/L0-demo/follow-up.md
- 格式：markdown 表格，列分别是 事项 / 归属人 / 紧急度 / 截止日期 / 来源会议
- 如果目录不存在，请先创建
完成后告诉我你创建/修改了哪些文件。
```
</details>

**👀 预期看到什么**
- Agent 会调用 `Write` 或类似工具，**真的在你电脑上创建文件**。
- 你能在 Finder/资源管理器里看到 `pm-agent-lab/news-lab/L0-demo/news.md` 这个文件。
- 用任何编辑器打开，里面就是刚才那张表。

**🤯 这一步要让你"破防"**：
现在回到窗口 A，让那个普通 Chat 也"把结果写到我本地 pm-agent-lab/..."。
它会**很有礼貌地告诉你它做不到**——它只能在对话框里输出文字，没有手。
**这就是 Chat vs Agent 最直观的差别。**

**⚠️ 如果出错怎么办**
- 偏差 A：Agent 说"我没有写入本地的权限" → 多半是客户端没开"允许写本地文件"，去设置里启用。
- 偏差 B：Agent 路径写错了，写到别处 → 纠偏：

  ```
  请先 ls 一下 pm-agent-lab/，确认当前路径，再把文件写到正确位置；写完再 ls 一次给我看。
  ```

---

### Step 4 · 让 Agent 自己"复盘"刚才做了什么

**🎯 你要做什么**
让它用自己的话总结一遍它刚才的动作链。这个总结你后面会用到。

**⌨️ 你输入什么**

```
请用 5 行以内回答：
1) 你刚才一共调用了哪些工具？
2) 它们是按什么顺序调用的？
3) 在哪一步你做了一次"看到结果再决定下一步"的判断？
4) 这件事如果不让你联网/不让你写文件，能完成吗？
5) 这是 Chat 做不到、但你能做到的核心原因是什么？
```

**👀 预期看到什么**
- 它会清楚地列出：搜索 → 读网页 → 整理 → 写文件 → 汇报。
- 关键句：它会主动指出"如果不让我联网/写文件，这事就完不成"——这就是 Agent 的本质。

把这段回答**保存到** `pm-agent-lab/news-lab/L0-demo/agent-vs-chat.md`，作为本讲学习笔记。

## 6. 思考题 & 下一讲引子

**思考题**
- 回看 Step 2 那个 prompt，如果你是 Agent，你会怎么决定**搜哪些关键词**？这反映了一个事实：你给目标越清晰，Agent 走弯路越少。
- 在你过去一周的工作里，**有哪 3 个任务**是你曾经"问过 Chat 但发现只能给空话"的？把它们记下来，L12 时我们会回来检视。

**下一讲引子**
L1 我们会用同样的"调研 + 落盘"流程，但把它做得更**结构化**——不是输出 markdown，而是输出可被下游消费的 JSON / 表格，为 L2 用 HTML 做可视化打地基。

## 8. 副线练习（可选 · 体验另外两个场景）

主线已经选了一个场景练手。如果时间允许，强烈推荐**再用另一个场景跑一遍 Step 1–3**——你会非常直观地感受到："同一套 Agent 能力，套到完全不同的工作场景上，方法是一样的"，这就是 PM 用 Agent 的"通用感"。

也可以挑一个**更贴近你真实工作的场景**：

- 候选场景：
  - 用户反馈：过去一周 App Store / 小红书 / 微博上对某产品的差评热点
  - 行业政策：过去一个月 `<你所在行业>` 的政策/合规变化
  - OKR 进度：当前季度你部门 OKR 各 KR 的最新进展（来自飞书文档）
- 期望产物：`pm-agent-lab/<自定义场景>-lab/L0-side/<主题>/...`

做完你会发现：**你越熟悉这个话题，你越能快速识别 Agent 输出里的"幻觉"和"敷衍"**。这种判断力就是 PM 用好 Agent 的核心肌肉。
