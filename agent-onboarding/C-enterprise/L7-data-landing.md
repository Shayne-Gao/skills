# Lesson 7 · Agent + 数据：文档 / 表格 / 知识库的落点设计

> 一句话定位：同一份数据，落到哪种载体，决定了它**未来一年的命运**。这一讲教你给每一份产物找到正确的家。

## 2. 背景小知识

L6 让你把数据送进了飞书，但你可能已经踩过这个坑：

> "我把所有产出都写到了一个长文档里，结果三个月后想找一条数据，翻了 20 分钟没找到。"

**载体选错，就是数据资产的慢性自杀**。

PM 时代有 5 类常见载体，各有强项：

| 载体 | 强项 | 弱项 |
|------|------|------|
| **本地文件** | 自由、零延迟、隐私好 | 别人看不到、易丢 |
| **飞书云文档** | 长文叙事、给人读、易转发 | 不可结构化筛选、批量操作差 |
| **飞书多维表格** | 结构化、可筛选、可计算、可视化 | 长文本写起来累 |
| **飞书 Wiki** | 长期知识沉淀、有目录 | 流转性弱、更新动力低 |
| **群聊** | 触达快、反馈即时 | 历史易丢、信息密度低 |

> 直觉口诀：**给人看用文档，给人筛用表格，给人记住用 Wiki，给人立刻看到用群，给自己折腾用本地。**

### Step 5 · 给"反例"加一条硬限制：群聊不存档

> 这是 PM 最常踩的坑：把重要数据丢群聊，三个月后翻不到。

**🎯 你要做什么**

```
在 ROUTING.md 末尾的"路由原则"里加一条硬规则：

"群聊永远不是数据的归宿，只是数据的'通知'。
任何重要资料发群之前必须先在文档/表格/wiki 里有一份持久化版本，
群消息只是带链接的提醒。"

并把这条规则也写到 wiki/README 使用契约里：当我让你"把 X 直接发到群"时，主动提醒我"先沉淀一份持久化的，再发链接"。
```

## 8. 副线练习（可选）

本讲主线已可在三个场景切换，副线建议挑战更进阶的玩法：

- **个人知识资产盘点**：让 Agent 扫你飞书空间，按 ROUTING 给出"哪些应当迁移到 wiki / 多维表格"清单
- **团队共享 ROUTING**：拉同部门 2–3 个 PM，合并各自版本成"团队 ROUTING v1"
- **历史多维表格治理**：选一张你团队混乱的老表，让 Agent 帮你梳理字段、合并重复列、补缺失值

## 9. 给 PM 的小结：落点设计的"四问"

任何要写下来的东西，开工前问自己：

1. **谁来看？**（决定语气和详略）
2. **要不要被筛选/聚合？**（决定是文档还是表格）
3. **多久后还会用？**（决定要不要进 Wiki）
4. **要不要别人立刻知道？**（决定要不要发群，但先沉淀）

四问答完，落点自然浮现——**不再需要拍脑袋**。
