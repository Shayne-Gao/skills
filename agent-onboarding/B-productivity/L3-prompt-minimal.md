# Lesson 3 · Prompt 工程的最小够用版

> 一句话定位：把"碰运气"变成"高命中率"——给 PM 一个 4 要素模板，5 分钟学会、终身受益。

---

## 1. 你将学会

- [ ] 我能用"角色 / 上下文 / 约束 / 产物" 4 要素模板，把任何模糊请求重写成高命中率 prompt
- [ ] 我能识别一个 prompt 为什么会让 Agent 跑偏，并准确加上缺失的那一块
- [ ] 我能把 L0–L2.5 用过的所有 prompt **倒过来**用 4 要素拆解、复盘自己的进步

---

## 2. 背景小知识

到 L2.5 你已经会"使唤"Agent 了，但多半还是凭直觉。**直觉的天花板就是：你不知道为什么这次结果好、那次结果差。**

PM 不需要研究学术意义上的 prompt engineering。**你只需要一个最小够用的 4 要素模板**：

```
[角色]   你扮演谁
[上下文] 我在做什么、当前情境
[约束]   不能做什么 / 必须遵守什么
[产物]   我要什么形态的输出、放在哪
```

口诀：**"角色定语气，上下文定方向，约束防跑偏，产物收住手"。**

> 大多数"Agent 不听话"，本质是这 4 块少了 1–2 块。L0–L2.5 你之所以能跑通，是因为我已经偷偷在 prompt 里替你补齐了这些；本讲是把方法论交还给你。

**⚠️ 如果出错怎么办**
- 偏差 A：Agent 还是写超长 → 你少写了"违反约束就重写"，纠偏：


  ```
  扫一遍你刚才的输出，列出违反"不要使用夸张副词"约束的所有词，然后改写。
  ```

### Step 3 · 反向拆解：把 L0–L2.5 的 prompt 对号入座

> 这一步是 PM 学习 prompt 的"开窍时刻"。

**🎯 你要做什么**
回到 [L1 Step 1](./L1-first-hands-on.md#step-1--先和-agent-一起定-schema字段定义) 的那段 prompt，把它**拆成 4 块**，写在 `before-after.md` 里。

参考拆法：

| 要素 | 对应原文 |
|------|----------|
| 角色 | （L1 没显式写，靠会话上下文撑） |
| 上下文 | "我要做一个'行业新闻周报'主线任务，每周抓一次新闻，存到本地，下游会用这些数据做 HTML 可视化。" |
| 约束 | "字段尽量原子化…必含…先不要去抓真实新闻…" |
| 产物 | "schema/news.schema.md……一条 mock 数据 sample.json" |

**📝 你在拆解中会发现的事**
1. 几乎所有"好用的 prompt"都在不知不觉里凑齐了 4 要素
2. 你之前写的 prompt **最常缺的是"约束"和"产物路径"**
3. **角色** 这一块 PM 经常忽略，但其实"你扮演谁"对语气和深度影响巨大

把 L0、L2、L2.5 各挑一段 prompt 重做这个拆解，每段写一两行心得。

### Step 5 · 升级技：让 Agent 帮你"挑刺自己的 prompt"

> 4 要素是底盘。下面这两个手法是"高级护栏"，遇到关键任务时再用。

#### 5.1 让 Agent 先 plan 再做

```
[在产物前面加一句]
开始动手前，先给我一份执行计划（步骤 + 你打算调用什么工具 + 大致顺序），让我确认后你再执行。
```

<details><summary>📋 切换到「需求池整理」场景的 prompt</summary>

```
[在产物前面加一句]
开始动手前，先给我一份需求池整理的执行计划（你打算从哪些来源抓线索 + 用什么字段去重 + 大致顺序），让我确认后你再执行。
```
</details>

<details><summary>📝 切换到「会议纪要跟进」场景的 prompt</summary>

```
[在产物前面加一句]
开始动手前，先给我一份会议待办提取的执行计划（你打算读哪些纪要文件 + 怎么区分"决策/待办/风险" + 大致顺序），让我确认后你再执行。
```
</details>

> 用途：长任务、不可逆任务、第一次跑的新流程。

#### 5.2 让 Agent 自己"挑刺"你的 prompt

```
我刚刚给你的 prompt 你先不要执行，按下面 5 个角度挑刺：
1) 4 要素哪块缺失或不清晰？
2) 哪些表述会被你理解成至少两种意思？
3) 有没有"约束太多反而互相打架"的地方？
4) 我有没有让你做一些其实你做不到 / 不该做的事？
5) 如果只能保留 1 句话，最关键的是哪一句？
给完反馈再等我确认要不要执行。
```

## 6. 思考题 & 下一讲引子

**思考题**
- 4 要素里 PM 最容易忽略哪一块？为什么？（提示：很多 PM 不写"产物"，导致 Agent 把答案丢在对话里就完事——这就是为什么对话越聊越乱。）
- 把 4 要素延伸成你团队所有同事都用的"团队 prompt 公约"，需要补哪一条？

**下一讲引子**
你已经会写好 prompt 了，但好 prompt 的"上下文"那块每次都要重写吗？显然不行。L4 我们会建一个 **LLM Wiki**——把"我是谁、我们产品是什么、我的偏好"一次性写好，让 Agent 永远从那里取材。

## 9. 给 PM 的小结：4 要素的"权重"

不是 4 块同等重要。按 PM 实际场景排序：

| 优先级 | 要素 | 写不好的代价 |
|--------|------|--------------|
| 🥇 | **产物** | 不写 → Agent 把答案丢在对话里，下游用不了 |
| 🥈 | **约束** | 不写 → 字数失控、风格漂移、瞎编内容 |
| 🥉 | **上下文** | 不写 → 答非所问、需要反复补背景 |
