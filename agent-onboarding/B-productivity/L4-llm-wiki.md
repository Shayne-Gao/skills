# Lesson 4 · 上下文管理：搭建你的 LLM Wiki

> 一句话定位：让 Agent 永远"记得"你是谁、产品是什么、偏好怎样——把"每次都要重讲背景"这个最大隐性成本一次性消掉。

---

## 1. 你将学会

- [ ] 我能搭一个**最小可用** `llm-wiki/`，让 Agent 每次回答前先读它
- [ ] 我能区分什么进 wiki、什么进 Skill、什么留在对话——三者各司其职
- [ ] 我能用 1 句话让 Agent 把"今天会议得到的新结论"自动写回 wiki

---

## 2. 背景小知识

到 L3 你写出了好 prompt，但你会发现"上下文"那一段每次都在重复——"我是 PM、产品叫 X、leader 偏好简洁……"。

**LLM Wiki = Agent 的私人维基**：把这些**长期不变 / 缓慢变化的事实**写进一份结构化目录，让 Agent 每次开工前先去查一遍。

它解决三件事：
1. **少打字**：你不再每次重写背景。
2. **少幻觉**：Agent 看了真实事实，比凭"记忆"靠谱。
3. **可演进**：新结论 / 新偏好可以**写回** wiki，越用越准。

> 直觉口诀：**对话是临时的，Skill 是流程，Wiki 是事实。**
> 三者搭配：Wiki 给 Agent "我是谁"，Skill 给 Agent "我怎么做"，对话给 Agent "我现在要什么"。

## 4. 实战任务

我们要建立的最小目录：

```
pm-agent-lab/llm-wiki/
├── README.md         # 索引：这本 wiki 有什么、怎么用、何时更新
├── me.md             # 我是谁（岗位、leader、汇报偏好）
├── product.md        # 我的产品：核心定位、关键模块、当前阶段
├── glossary.md       # 我们公司/团队的"黑话词典"
├── stakeholders.md   # 主要协作方（研发、设计、运营、外部合作方）
└── memory.md         # 自由记忆：随时被 Agent 写入的临时事实
```

### Step 1 · 让 Agent 帮你"采访"自己

> 不要自己闭门写 wiki——会写得太"官方"。**让 Agent 当记者来采访你**，速度快 5 倍，且更接近你真实工作语境。

**🎯 你要做什么**

**⌨️ 你输入什么**

```
我要建一个 llm-wiki，让你以后每次回答前都先读一遍它。

现在先帮我"采访我自己"，把以下 4 个文件填出来：
- me.md（我的岗位、leader、汇报偏好、工作节奏）
- product.md（我的产品定位、关键模块、当前阶段、核心指标）
- glossary.md（公司/团队黑话词典，先 10 个）
- stakeholders.md（≥3 个核心协作方，他们在意什么）

采访方式：
1) 一次只问 1 个问题，等我回答再问下一个
2) 每个文件最多问 5 个问题，问到差不多就停
3) 全部问完后**先汇总给我看**，不要立刻写文件
4) 我确认后，再写到 pm-agent-lab/llm-wiki/ 下对应文件

约束：
- 不要替我编内容；我说"跳过"就跳过
- 文件内容简洁，每个 ≤ 200 字
```

### Step 2 · 给 wiki 写一个"使用契约"

> 没有契约的 wiki 等于没有 wiki——Agent 不会主动去读。

**🎯 你要做什么**
让 Agent 写 `README.md`，并在里面**告诉未来的 Agent**怎么用这本 wiki。

**⌨️ 你输入什么**

```
帮我写 pm-agent-lab/llm-wiki/README.md，包含：

1) 这本 wiki 的目的（2 句话）

2) 一份"使用契约"，明确告诉将来读到这份 README 的 Agent：
   - 在 pm-agent-lab/ 下任何任务开始前，必须先读 llm-wiki/me.md 和 product.md
   - 当我提到"老板/leader/我们产品"等代词时，应当主动从 wiki 取上下文
   - 当对话里出现一个 wiki 里没有的新事实，且我说"记下来"时，应当 append 到 memory.md
   - 涉及具体协作方时，先查 stakeholders.md
   - 涉及黑话/术语时，先查 glossary.md

3) 一份"何时更新"清单：哪些事件触发 wiki 更新（OKR 调整 / 转岗 / 新产品 / 新 leader 等）

4) 一份"红线"：哪些信息不能写进 wiki（例如：未公开的财务数字、用户隐私）
```


## 7. 本讲交付物

按你选定的场景，下面三选一即可（`llm-wiki/` 主体共享，仅"场景专属文件"按场景区分）：

```
pm-agent-lab/
└── llm-wiki/                        # 三场景共享：个人级长期事实
    ├── README.md                    # 使用契约 + 何时更新 + 红线
    ├── me.md
    ├── product.md
    ├── glossary.md
    ├── stakeholders.md
    ├── memory.md                    # 持续被写入的临时事实
    ├── WIKI_CHECKUP.md              # 每月体检 prompt
    │
    ├── competitor-snapshot.md       # 📰 news 场景专属：你长期盯的几家竞品快照
    ├── backlog-priorities.md        # 📋 backlog 场景专属：需求优先级口径
    └── meeting-decisions.md         # 📝 meeting 场景专属：在跟进的关键决策清单
```

> 三场景只新增**1 个**场景专属文件，其余 wiki 主体复用——这正是 wiki 的价值：人是同一个人，场景换了只换那 1 份"侧重点笔记"。

## 8. 副线练习（可选）

本讲主线已可在三个场景切换，副线建议挑战更进阶的玩法。把 wiki 拓展到一个具体业务方向：

- 增加 `competitors.md`：你重点关注的 3–5 家竞品的定位、最近动作、自家差异点
- 增加 `metrics.md`：你产品的核心指标定义、计算口径、目标值（注意红线：不要写未公开数字）
- 增加 `decisions.md`：重大决策记录（每条 ≤ 5 行：背景 / 选项 / 决定 / 当时反对意见）

> `decisions.md` 是 PM 在 Agent 时代最被低估的资产：它能让 Agent 在你下次决策时主动提醒"上次类似情况你是这么决定的"。

## 9. 给 PM 的小结：Wiki / Skill / 对话 三件套

| 形态 | 装什么 | 例子 | 寿命 |
|------|--------|------|------|
| **Wiki** | 长期事实 | 我是谁、产品定位、leader 偏好 | 月级 / 年级 |
| **Skill** | 重复流程 | 周报生成、新闻调研、需求池整理 | 季度级 |
| **对话** | 当下意图 | "帮我做这一次的 X" | 单次 |

记住这张表，**你就掌握了 Agent 时代 PM 的"个人知识架构"**。
