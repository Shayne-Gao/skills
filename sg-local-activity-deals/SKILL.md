# Singapore Local Activity Deals

这个 skill 用于持续抓取、更新和整理 `新加坡本地活动 + 优惠信息`，重点覆盖：
- 最近 `7-30 天` 内值得关注的活动
- `免费`、`1-for-1`、`半价`、`特价`、`限时促销`
- 小红书 / B站 / 官方页 / 官方票务页的交叉验证
- 适合直接给用户做决策的表格或 HTML 输出

当用户出现以下意图时，优先使用本 skill：
- “搜一下最近新加坡有什么活动”
- “抓一下新加坡最近的便宜活动 / 免费活动 / 薅羊毛活动”
- “查一下 1-for-1、半价、买一送一”
- “用小红书 / B站 / 社媒看看最近都在说什么”
- “把这些活动整理成表格 / HTML / shortlist”

## Core Rule

这个 skill 的核心不是“泛泛搜活动”，而是要更像一个 `新加坡活动优惠雷达`：
- 优先抓 `未来一个月` 内能去的活动
- 优先抓 `免费 / 便宜 / 限时 / 错过会后悔` 的活动
- 不能只看社媒标题，必须尽量点开正文
- 不能只给模糊推荐，必须尽量补：
  - 活动类型
  - 时间
  - 地点
  - 折扣方式
  - 原价 / 折后价
  - 参与条件
  - 来源链接

## Required Source Stack

执行时优先按以下信息层级工作：

1. `小红书`：找中文用户视角和羊毛线索
2. `B站`：补视频/活动攻略/中文解释
3. `官方页 / 官方票务页 / 官方权益页`：核价格、核时间、核规则

如果用户明确要求用小红书、B站、网页查，必须：
- 先使用 `agent-reach` 相关能力
- 按当前环境可用后端执行
- 不要绕过现有互联网技能，自造抓取方案

## Small Red Book Rule

这是本 skill 最重要的规则之一。

### 不允许只看标题

如果小红书搜索结果里出现：
- “7 月活动合集”
- “免费活动合集”
- “这周末去哪玩”
- “优惠大全 / 羊毛合集”

必须尽量点开正文，而不是只根据标题输出。

### 必须拆合集帖

如果一篇小红书正文里列了多个活动，必须：
- 把每个活动拆成单独条目
- 不能只把整篇合集当作一行

例如：
- 同一篇里写了 `NDP 烟花预演`
- `美食节市集`
- `圣淘沙免费露天电影`
- `F1 后台开放日`

这些都应拆成独立表格行。

### 必须保留原帖链接

所有来自小红书的线索，只要能拿到具体笔记链接，就必须保留：
- 小红书原帖链接

如果正文读到了具体条件，也要在输出里写：
- “小红书正文说了什么”

## Pricing Rule

关于价格必须遵守以下顺序：

1. 先找 `官方现价`
2. 再找 `官方原价`
3. 如果官方没有完整原价，再找：
   - 商家菜单
   - 官方票务页
   - 小红书正文里的价格表述
4. 如果仍然没有原价，明确写：
   - `原价未找到`
   - `正文仅写现价 / 折扣方式`

### 对 1-for-1 的特殊要求

如果是 `1-for-1 / 买一送一`：
- 尽量补单件原价
- 尽量换算成：
  - 双人总价
  - 人均价格

例如：
- 原价 `S$21.90`
- 1-for-1 后两份共 `S$21.90`
- 可写成 `人均约 S$10.95`

### 对平台券的特殊要求

如果是 Klook / Trip / OTA 券码：
- 要写清楚这是 `平台券`
- 不要伪装成景点官方折扣
- 最终要提醒用户：
  - 下单页再试码
  - 有品类 / 时段 / 库存限制

## Deal Priority Rule

输出时优先级从高到低：

1. `免费`
2. `1-for-1`
3. `半价 / 50% off`
4. `明确可换算的 20%-40% off`
5. `限时低价 / 开业活动 / 附赠礼品`
6. `只是普通会员价`

如果只是长期常驻会员折扣，而不是明显促销：
- 降低优先级
- 不要包装成“很值得冲”的活动

## Verification Rule

每条活动要尽量给一个置信层级：

- `高`：官方页 / 官方票务页能直接确认
- `中高`：小红书正文很具体，且能被官网或媒体部分印证
- `中`：小红书正文有细节，但官网未完全对上
- `低`：只是社媒线索，无法确认

如果用户说“给高准标签”，就把这个置信信息明确放进表格。

## Default Output Shape

默认输出优先用表格。

推荐列：

| 活动 | 中文说明 | 活动类型 | 时间 | 地点 | 优惠方式 | 原价 | 折后/现价 | 小红书正文说了什么 | 官方/补充说明 | 置信度 | 链接 |

### 输出风格要求

- 可适度使用 `**加粗**` 强调重点
- 重点优惠可以用 `<u>下划线</u>` 强调
- 如果用户明确要 HTML，则转成结构化 HTML
- 如果用户只是要文本总结，先给表格，再给 Top5 建议

## HTML Rule

如果用户要求 HTML：
- 默认输出高信息密度页面
- 支持按：
  - 免费
  - 1-for-1
  - 半价
  - 平台券
  - 线索待核
  - 亲子 / 情侣 / 夜场 / 市集
  做筛选

HTML 中应尽量包含：
- 中文标题
- 英文原名
- 优惠标签
- 时间
- 地点
- 原价 / 折后价
- 小红书原帖
- 官方页

## Recency Window

默认时间窗：
- `今天起未来 30 天`

如果用户说：
- “最近”
- “这周”
- “下个月”

则按用户时间窗调整。

## Standard Workflow

### 1. 明确时间窗
- 默认未来 `30 天`

### 2. 先跑社媒
- 小红书搜：
  - 新加坡 免费 活动
  - 新加坡 1-for-1
  - 新加坡 半价
  - 新加坡 七月活动 / 八月活动
- B站搜：
  - 新加坡 活动
  - 新加坡 免费
  - 新加坡 打折

### 3. 点开正文
- 至少读几篇：
  - 合集帖
  - 单独优惠帖
  - 周末活动帖

### 4. 拆条目
- 一篇合集里每个活动拆成单独记录

### 5. 官方核验
- 用官网 / 票务页核：
  - 时间
  - 地点
  - 原价
  - 折后价
  - 条件

### 6. 输出结果
- 先表格
- 再给：
  - Top 5 最值得冲
  - 哪些是“纯免费”
  - 哪些是“真 1-for-1 / 真半价”

## What To Avoid

- 不能只看小红书标题
- 不能把合集帖整篇当一个活动
- 不能把平台券说成官方折扣
- 不能在没有依据时伪造原价
- 不能把长期会员价说成限时强促
