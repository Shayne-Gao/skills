# Recommendation Framework

## Goal

把“最近看到哪些价格”转成“现在应该怎么买”。

## Recommendation Dimensions

每次建议至少从这些维度看：
- 当前价格是否接近好价
- 关键参数是否真的强
- 口碑是否稳定
- 是否适合用户的使用场景
- 是否存在更好的替代项

## Required Recommendation Answers

最终建议至少要明确回答：
- `最推荐买哪个型号`
- `它的合适价格是什么`
- `当前推荐清单里还有哪些型号性价比也不错`
- `是否建议现在下单`

## Price Band Rule

尽量给出价格带，而不是只有一个点价。

例如：
- `闭眼买价`
- `可以入手价`
- `不着急可以等等的价`

如果历史价格不足：
- 结合当前主流成交价、活动复杂度、竞品对比给出相对价格判断
- 同时明确标注 `历史样本不足`

## Recommendation Tiers

推荐可分为：
- `首推`
- `次选`
- `预算友好`
- `观望`

## Decision Rule

### 1. 首推

满足大部分条件：
- 参数在当前价格带明显占优
- 口碑问题不明显
- 当前价格已经接近合理好价
- 对目标用户场景适配度高

### 2. 次选

常见原因：
- 价格略高但参数更强
- 或参数略弱但价格特别合适
- 或适合不同偏好人群

### 3. 预算友好

常见原因：
- 核心需求能满足
- 价格显著更低
- 但会在参数、体验或长期耐用性上让步

### 4. 观望

常见原因：
- 当前价格不够好
- 口碑明显有坑
- 参数公开不透明
- 存在更优替代

## Output Structure

建议输出包含：
- 结论摘要
- 主力型号横向比较
- 分预算建议
- 分人群建议
- 当前是否值得下单
- 等待什么条件再买

## Writing Rule

- 尽量说人话，但结论要具体
- 避免只说“不错”“一般”“中等”
- 能给硬参数就给硬参数
- 能给价格带就给价格带
- 能说清楚适合谁/不适合谁就直接写出来
