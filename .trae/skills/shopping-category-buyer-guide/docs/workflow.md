# Workflow

## Goal

把一个商品品类请求转成完整选购闭环：
- 抓近期什么值得买好价
- 找主力型号
- 建参数库
- 汇总口碑
- 输出建议
- 落盘可复用结果

## Inputs

必填：
- `category_query`，例如 `除螨仪`

可选：
- `budget_min`
- `budget_max`
- `use_case`
- `must_have_features`
- `avoid_features`
- `need_html_output`

## Steps

1. 确认品类与场景假设
2. 在什么值得买搜索近期相关结果
3. 过滤噪音项并抽取候选型号
4. 对候选型号去重、归一和归组
5. 统计每个型号的当前可见价格与热度
6. 选出主力研究型号
7. 从外部来源核实关键参数
8. 汇总公开评价的主要优点与槽点
9. 先判断 exact 型号近期低价、常见价与当前价位置
10. 生成一张本轮主力型号参数对比表
11. 再给出推荐型号、好价带与是否建议现在买
12. 将价格记录、型号参数、对比表和结论落盘

## Default Window

如果用户没有指定范围：
- 先看什么值得买搜索前 `3-5` 页
- 先覆盖当前最常见、最有热度的型号
- 先做第一轮可决策版本，再按需要扩页

## Core Decision Questions

每次都尽量回答：
- 这个品类目前最值得买的是谁
- 各主力型号的合理入手价大概在哪
- 今天的价格相对前几天是更便宜、差不多，还是涨回去了
- 当前出现的价格是否达到“近期好价”
- 现在下单值不值，还是更适合等
- 不同预算/诉求下分别该怎么买

## Delivery

默认文本交付至少包含：
- 本轮抓取范围
- 归一后的型号列表
- 参数对比表
- 推荐结论

这里的“参数对比表”是强制项：
- 每次抓完新数据都要更新
- 不能只给结论不出表
- 如果参数不完整，也要先产出带 `null` / warning 的表

如果用户要求更好读的结果，可额外生成：
- Markdown 表
- HTML 宽表
- HTML 决策页

默认优先级：
- 至少给 Markdown 表
- 如果用户偏好可视化或横向比较，再补 HTML 宽表

## Failure Handling

- 如果什么值得买搜索结果很杂，先缩小关键词，再做第二轮抓取
- 如果型号抽取歧义大，先保留 `系列组`，不要强行拆到具体 SKU
- 如果参数公开源冲突大，保留多口径并降置信度
- 如果历史价格样本不足，明确说明当前只做“相对静态”推荐
- 如果只有系列组历史价，没有 exact 型号历史价，必须明确说明不要把系列最低价直接当成该型号历史最低价
